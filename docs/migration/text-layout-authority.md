# OCR 文字排版的后端统一记录

所有引擎先用 OCR 四边形定位并校正方向，再在原始影像裁剪块中提取深色文字笔画带，排除检测框留白和边缘稀疏干扰后计算字号、中心位置、文字宽高和基线偏移，统一保存到 text_attribute 与 feature。字号按服务器所用字体的实际字形高度计算，宽度采用笔画范围；前端只读取这些值绘制，不再推断 OCR 字号、读取浏览器字形宽度后补偿，也不把小角度倾斜归零。

新增 layout_width_px、layout_height_px、baseline_offset_px、layout_basis 为可导出、可保存的排版字段。layout_basis=ocr_ink_v3 表示根据原图笔画校准的排版，ocr_quad_v2 表示源笔画证据不足时的保守检测框估算，manual 表示用户改过排版，legacy_estimate 表示尚未修正的旧估算。font_family 保存服务器用于测量的字体名，当前 Windows 环境采用 Microsoft YaHei。具体扫描字体仍不能仅靠 OCR 准确恢复；原始影像和候选四边形保留供核对。

新候选创建、面线文字联合采用、另建项目采用均写入相同排版。OCR 更新已有人工文字时维持用户位置与排版意图，并标记 manual。显式修改文字内容、字号、角度或位置时退出自动检测框排版；仅改颜色和确认文字不改变排版。

restore_ocr_layout 是标准编辑命令，带工作修订、幂等键与撤销重做证据。它可针对当前资产或所有资产，使用真实候选四边形修正既有自动文字，保留审核记录和文字内容。人工补录、已修改内容、历史中显式改变排版的对象跳过。候选中的规则建议保留为待选择证据；默认采用 OCR 原文，只有显式提交文字值才采用建议或人工校正，不因近形字符或地质代号规则自动改写内容。

数据库升级仅增加字段，不悄悄修改历史几何。现有项目通过备份和正式命令更新，冻结快照及以往导出保持原状。新快照、Pixel JSON、GPKG、SHP、GeoJSON 属性与兼容导出清单携带同一组后端排版数据；旧格式无法表达的宽度和基线字段由兼容清单保留。

验收覆盖小角度、倾斜中文、长英文、上下标、候选直接采用、联合采用、人工编辑保护、颜色修改、命中索引、保存重开、快照恢复、撤销重做及导出回读。全图字号和旋转的尺度均为原图像素坐标，画布缩放不修改存储值。

## 原图笔画校准与上下标

OCR 检测框包含留白，不能将字形拉伸填满。原图裁剪通过中性深色和局部明度对比提取笔画，使用横向笔画密度定位主文字带，边缘网格线或孤立灰尘不应决定字号。对于空白、灰尘占主导或过小区域，保留保守估算，不声称恢复了原字号。源图与其他线网重叠时仍可能不确定，当前方法属于启发式定位，不能保证每个字像素级一致，必须用原图对照验收。

layout_runs 是持久化的排版分段数组，含 text、script（normal/subscript/superscript）、font_size_px、x_offset_px、baseline_offset_px、width_px、source_index、basis、review_required。Unicode 上下标先还原为普通字形再按分段字号与基线绘制，避免字体自身下标再次缩小。普通数字不因字符规则强制变成下标；较小数字在主文字带上方/下方的几何证据用于判断上标或下标。字符分离不足或规则与图像冲突时，分段标为待核对，原 OCR 原文和当前文字不重写。没有原图证据的 Unicode 上下标也保留分段结构并标为待核对。

前端以 tspan 分别绘制后端分段，不独立计算字号和角度。JSON/GPKG/SHP/GeoJSON 导出携带完整分段；GIS软件若未配置分段标签渲染不会自动获得相同外观，兼容导出清单保留无法表达的元数据。

## 2026年11月9日候选身份与竖排核查

相同位置的判定使用实际四边形重叠，避免相邻斜排文字的轴对齐外框互相覆盖造成误合并。多尺度留白导致一个框包含另一框时，仅在中心距离、包含程度和面积比例同时满足保守约束后认作同位置。相同位置同文采用 NFC 规范等价比较合并，每个尺度与引擎的原始候选平铺保留在 source_candidates；冲突读法保留为待核对候选，自动采用不生成重叠文字。规则不使用 NFKC 统一地质代号或近形字。

重复采用同时比较原始 OCR 来源、人工修正后的现文字与当前占据范围；同文返回 OCR_DUPLICATE_TEXT，同位置不同读法返回 OCR_POSITION_CONFLICT，均需定位原对象或明确更新。显式更新同文只更新候选关联，原字号、位置、方向及全部排版分段保持；改变内容后继续保留用户的字号和位置，文字范围转为人工排版。

竖排以检测四边形的阅读方向识别，不把接近竖直的斜排横串改成逐字竖排。有原图笔画证据时以每个字的实际范围、中心与字高保存 ocr_vertical_ink_v2 和 source_ink_vertical 分段，检测留白不放大字号；证据不足继续保留 ocr_vertical_v1 检测框估算。Unicode 上下标回退排版的整体范围覆盖实际分段字形与基线，分段没有图像证据时仍标为待核对。

真实原图重新运行 Rapid 两尺度得到 123 条原始候选，融合为 94 条，其中 22 条冲突候选留待核对，自动采用 72 个文字且未出现同文中心相距 3 像素内的重复对。已核查青岚镇、北岭断裂、山前带、小字 silt 和 K1 的局部原图与持久排版，另建项目采用及重开读取一致；仍存在 Qh/Oh、北岭断裂/北岭斯裂等 OCR 内容分歧。此结果证明这些入口与选定局部的行为，不构成整图准确率或全部漏检、误检通过。证据在 runtime/remediation-20261109/ocr-real-evidence.json。
