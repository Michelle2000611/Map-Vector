# Map-Vector

依据 20261106/Map-Vector_新项目迁移技术设计.docx 实施的独立迁移工程。FastAPI 提供 /api，React 提供项目与底图、识别任务、编辑与审核、质量与范围、保存与导出五步界面。每个项目的 state/project.sqlite 是编辑真值；GIS 输出是固定快照的派生成果。

2026年11月8日问题清单修复涉及任务防重复、方向/颜色/有效掩膜、GIS回读与放行政策、保护线清理、候选去重、固定样本漏线和竖排、外部配准及GIS交付包。实现与验收边界见 [修复验收记录](docs/migration/20261108-remediation-acceptance.md)。ArcGIS实机验收需在安装ArcGIS Pro/ArcPy的环境完成，交付包内附脚本。

2026年11月9日继续修复真实SHP排版字段回读、未提交属性草稿、OCR同位冲突与人工修改保护、文字笔画掩膜、变宽线和自动编组，并验证完整清理的撤销/重做。草稿刷新可恢复，离开有提醒；差异图注明面线范围，刷选支持三种命中规则。最终结果和仍需核对的真实字符分歧、跨底色区域、复杂附加形状见 [本轮整改与验收](docs/migration/20261109-remediation-acceptance.md)。新算法不批量替换原项目的人工工作。

## Windows 安装和启动

需要 Python 3.11 和 Node.js。API、B2c、RapidOCR 共用根目录 .venv，安装缓存也进入 .venv。首次执行 powershell -ExecutionPolicy Bypass -File scripts/install.ps1；完成后执行 powershell -ExecutionPolicy Bypass -File scripts/start.ps1，或双击 scripts/start.cmd。

打开 http://127.0.0.1:8840/projects；接口文档 /docs，健康检查 /api/health。MAPVECTOR_API_PORT 可改端口，启动器检查占用。PyCharm 选择 .venv/Scripts/python.exe，以 mapvector 模块运行，工作目录为项目根目录。

Paddle 与主环境有 NumPy 冲突，使用 .venv-ocr-paddle 隔离，安装脚本 scripts/install-paddle.ps1。此环境不安装 API 包。模型不自动下载；models/rapid、models/paddle 的 manifest.json 固定所需文件和 SHA256。缺模型或哈希不符时诊断报错；可选 OCR 失败保留已完成的面线工件。

执行 .venv/Scripts/python.exe scripts/diagnose.py 查看解释器、依赖、模型、前端状态。前端修改后执行 npm --prefix frontend run build；开发执行 npm --prefix frontend run dev。

### PyCharm 中分别启动前后端

在项目根目录的两个 PowerShell 终端标签中分别执行：

- 后端：.\scripts\start-backend.cmd，使用项目 .venv，默认 http://127.0.0.1:8840。
- 前端：.\scripts\start-frontend.cmd，启动 Vite，地址 http://127.0.0.1:5175，API 代理至 8840。

开发时访问前端 5175 页面，两个终端各自用 Ctrl+C 停止。8840 已有后端运行时可直接复用，重复启动会报端口占用。

项目 .run 目录提供 Map-Vector Backend（Python 模块）和 Map-Vector Frontend（npm run dev）两个 PyCharm 运行配置，可从顶部运行配置选择器启动；Frontend 配置需要 PyCharm 支持 Node.js/npm。终端启动脚本同样可直接使用。原 scripts/start.ps1 保留构建后由后端同源交付页面的方式。

## 使用和存储

步骤 1 直接选择或拖入原图，后端在验证文件后用文件名（不含扩展名）创建项目；顶部名称可修改，内部项目和文件身份由后端生成。导入前隐藏文件与页面表格，导入后显示真实文件格式、页码和像素尺寸。原图按 100% 像素显示，预览区随图像高度展开，超宽图像可横向滚动。PDF 显示指定 DPI 渲染的当前页，可在页面设置中切换页码。

步骤栏只允许回到前面的步骤，向前通过页面底部的“进入步骤”按钮依次前进。步骤进度保存在项目中；直接访问尚未到达的后续地址会回到已到达的步骤。步骤 1 只展示导入、文件信息和原图预览。

步骤 2 选择“面和线”“面、线和文字”或“仅文字”；涉及文字时再选择 RapidOCR/PaddleOCR 引擎。环境检查状态在识别任务栏内显示，详细诊断默认折叠。识别完成后提供绑定该次任务的只读预览，可切换全部、面、线、文字；纯面线任务的文字页明确提示本次未运行 OCR。保存识别结果后进入步骤 3“编辑与审核”的统一工作区，通过“选择与工具”切换面、线和文字图层。审核列表支持分数与原因、可选抽查以及定位残影预览，待审项不阻止继续编辑。

编辑与审核共用一个持续挂载的画布工作区。选择文字图层时，左右画布下方显示“文字核对”；通过待核对、稍后处理、已确认、全部筛选文字。主表保留文字、原始候选、识别分数、上下标、需核对项、状态与“查看”，残影扫描按同一文字身份合并为独立证据列；人工核对状态与残影建议各自独立。右上提供“检查全图残影”“更多”和刷新。门槛、重新评估、恢复识别排版及未采用结果收入“更多”。切回面或线时隐藏并保留筛选、门槛和分页，画布缩放、滚动和比较布局也保持不变。定位文字后列表保持展开，画布显示选中对象。工具区的不透明度滑块拖动时实时预览当前图层，松开后单次保存。单个面、线、文字对象的合法属性输入立即预览，停顿约600毫秒或失焦后自动保存；无效输入、中文输入法组合和失败修改保留草稿。多选不同值显示“多个值”，通过“应用到 N 个对象”一次原子更新实际改动字段。保存状态及失败重试位于属性面板中，空选区也能恢复旧对象保存失败。审核、残影清理、编辑命令仍使用各自的业务数据与持久化记录。进入“质量与范围”直接从统一工作区推进。持久化阶段编号没有重排：旧阶段 2、3 都显示为步骤 3，阶段 4、5 对应步骤 4、5；服务端允许旧审核/编辑阶段直接进入阶段 4，跳过识别或空原图仍会拒绝。旧 `/review` 路径会重定向到 `/editing?mode=review` 并初始化文字图层；切回面或线后同步更新 URL，刷新时保持对应的编辑入口。

文字引擎也可选择“RapidOCR + PaddleOCR 联合识别”：两套引擎依次运行，相同文字且位置重叠的候选合并，保留两套来源；同位置文字不一致时保留候选并标记待核对，采用面线结果时不会自动生成这些冲突文字。每个引擎的原始结果独立留存。单引擎失败会保留另一引擎成果并报告警告，两者均失败的纯文字任务报告失败。联合模式耗时通常高于单引擎模式。

保存识别结果前读取服务器最新项目修订和任务状态，并检查任务资产与当前资产一致；保存期间发生并发编辑时保留后端修订检查，刷新内容后要求用户重新提交，不自动重试替换。已有编辑内容时要求明确选择替换或另建项目。

上传后可按页和 DPI 生成独立资产。采用另一资产、采用识别结果、恢复快照均保留历史。后台识别不会覆盖人工工作。文字内容修改、明确确认、自动放行、残影清理和隔离分别记录。

未完成审核可保存工作草稿。正式导出使用 baseline_compatible 政策，并单列审核状态与依据。像素坐标原点为左上角，x 向右、y 向下；像素项目可输出 GPKG/SHP/pixel_json。GeoJSON 需要配准并转换到 WGS84。

ROI 支持整图、保留跨界和实际裁切；输出读取所选快照中的 ROI。SHP ZIP 包含确定短字段映射、完整属性和来源关联清单。工作数据位于 workspaces/default；临时文件、日志、运行证据位于 runtime。数据、模型权重和虚拟环境均不入 Git。旧工程只读。

## 迁移和备份

检查：.venv/Scripts/python.exe scripts/migrate.py dry-run <旧项目目录> --output runtime/migration/dry-run.json。将 dry-run 改为 import 生成新项目。verify <新项目目录> 检查 SQLite、工件哈希和几何；scan、report 同样可用。来源不能证明的工程进入隔离报告。

备份：.venv/Scripts/python.exe scripts/backup.py create <新项目目录> <备份ZIP>。恢复：.venv/Scripts/python.exe scripts/backup.py restore <备份ZIP> <独立目标工作区>。目标存在时拒绝覆盖，备份前完成或取消运行中的识别和导出任务。

明确交回旧编辑器：.venv/Scripts/python.exe scripts/export_legacy.py <新项目目录> <snapshot_id> <独立输出.gpkg>，默认草稿，--formal 使用原审核门禁，--scope 支持 full/keep_crossing/clip。兼容清单保留新系统身份与无法由旧格式表达的字段，输出路径存在时拒绝覆盖。

## 验证

后端：.venv/Scripts/python.exe -m pytest backend/tests -q。前端：npm --prefix frontend run build；服务启动后 npm --prefix frontend run test:e2e。浏览器使用本机 Edge，样本由测试自身提供。

契约：.venv/Scripts/python.exe scripts/generate_contracts.py；再执行 frontend/node_modules/.bin/openapi-typescript.cmd contracts/openapi.json -o frontend/src/services/generated.ts --default-non-nullable false，保持后端默认参数在请求中可省略。

逐项迁移和证据见 docs/migration/acceptance-report.md 与 implementation-plan.md。自动验证不替代真实错误整改和外部 GIS 人工验收。许可证边界见 NOTICE.md。

页面导出使用持久后台任务，受理后可继续编辑；阶段、等待时间、取消与错误在保存导出页展示，完成并回读成功后才出现下载。任务日志可在识别页读取。应用边界和状态契约见 docs/migration/architecture-completion.md。

点选使用 SQLite 空间索引筛选邻近候选，再按原面、线和旋转文字命中规则精确判断；复杂区域选取仍使用原算法。前端缓存图形路径并复用静态图层，选中高亮单独绘制，减少点击和缩放时的全量重绘。

滚动条和平移使用原生视口同步，程序同步事件不作为新拖动源回传，滚动不触发整页渲染。大量选择采用分批高亮；替换选区不传旧选区，批量 ID 统一校验。编辑页使用历史摘要接口（include_results=false）保留撤销重做信息，完整结果按原接口读取。框选、刷选、套索先按空间索引筛选，再按原有几何规则判断。后台识别和导出轮询避免重叠请求，闲置页面停止计时刷新。

文字残影显示开关置于画布标题栏右侧；右侧清理计划显示实际合并、隔离及保留数量。清理已有文字的面线时，文字内容、几何、字号、角度、颜色、原 OCR 关联与审核证据保持不变。

OCR 文字按原图像素范围在后端确定并保存排版，历史自动文字也通过可撤销命令统一修正；前端直接使用后端字号、角度、宽高及基线偏移，人工明确修改过的字号和位置保留。原图用于核查真实字形，可编辑文字使用字体重绘，不承诺恢复原扫描字体。

加载反馈参考 Geological-Map-Digitizer 的 Ant Design 顶部转圈提示。数据、图像、操作预览与提交均显示加载提示；并行请求共用提示，结束、失败、取消或切换页面时清理。后台识别与导出持续显示任务提示，进度轮询不重复弹出。

文字残影清理：选中文字后直接点击“清理残影”，后台自动计算完整计划并提交，不要求先点击预览。“查看范围”仅生成只读高亮，清理范围显示一行数量，依据收入详情。清理保留现有跨框线、待核对线及地质边界保护规则；归属无法确定、计划过期或复查仍有残影时整次取消或回滚。文字内容、排版和原图像素保持不变，成功可撤销和重做。“确认并下一条”先等待有效属性保存，再独立确认当前文字并定位下一条；自动保存不代表人工确认。稍后处理和下一条同样先协调保存，非法或失败输入保留在原对象。保存中继续输入按最新内容合并，不覆盖后续草稿；撤销等到同资产旧对象保存尾部结束后执行，防止迟到写入反向覆盖撤销。步骤3移除图例样式编辑，操作历史使用中文动作和状态。

OCR 排版由后端统一持久化：font_size_px、rotation_deg、font_family、layout_width_px、layout_height_px、baseline_offset_px 和 layout_basis。新采用 OCR 文字按原始四边形的主轴角度和像素宽高计算排版，字号使用服务器所选字体的真实字形高度度量；前端直接绘制存储值，不再独立修正字号或角度。恢复原图文字排版命令可修正现有自动文字，记录修订并可撤销，人工排版修改受保护；保存重开、命中区域和新导出使用同一组数据。冻结旧格式渲染器无法表达宽度约束时，完整排版信息保留在兼容清单中。

文字排版的完整后端契约及旧数据修正规则见 docs/migration/text-layout-authority.md。字号不再用浏览器测量结果临时覆盖；宽度限制和基线对齐所需的数值也保存在数据库并进入新快照与导出属性。

原图笔画校准：OCR检测框留白不参与字号放大，优先按原图实际笔画带建立排版；不清楚的区域保留估算。文字层支持后端持久化的 normal/subscript/superscript 分段（layout_runs），每段有独立字号、横向位置和基线；前端直接渲染并在审核表显示上下标及待核对标记。

连续文字预览：局部预览使用当前共享修订和选区，遇到修订冲突时同步数据并重试一次，只读恢复不自动重试清理写操作。生成状态及失败说明位于对象操作区。字号、角度、X/Y输入左侧带标签，默认最多显示1位小数，未修改字段保留原后端精度。项目操作历史移入工具栏的独立底部抽屉，不再混入对象属性。步骤3和4的合并仍待方案讨论，本轮不修改工作流阶段。

对象属性面板按外观属性、选择与编组、几何工具、对象来源组织；删除入口位于对象来源下方，面、活动线、隔离线和单文字均可撤销。删除面只移除指定几何并留下空缺，不自动扩张邻面，索引、编组和样式关联同步保留历史。新对象绘制参数不修改已有选区。自动保存与面删除的事务、异步和实机副本验证见 [属性面板与自动保存验收](docs/migration/20261109-property-autosave-acceptance.md)。更新这些后端命令后，需要重新启动已运行的后端进程以加载新版接口。

面几何修复：属性区外观、文字核对和残影处理均默认展开且可折叠，普通操作使用默认按钮，删除保留危险样式。文字表支持本页勾选批量删除，翻页/筛选/对象离开可见页时清空选择；面线仍使用画布选区，底部来源之后显示删除数量。面工具增加“去除线状附着”和“填充孔洞”：先生成修订绑定候选，窄枝须选择共边接收面，涉及保护线/文字时逐项核对后只调整面归属；真正空洞才允许填充，被占用孔需核对后使用面合并。修复保留独立线文、不产生新增空隙重叠，可整次撤销；原始B2c识别默认行为未被自动替换。实现、真实副本和限制见 [面修复与批量操作验收](docs/migration/20261110-face-repair-and-review-acceptance.md)。
